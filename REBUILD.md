# REBUILD.md — Exact rebuild instructions (for humans and AI agents)

This document is enough for **any AI or developer on another machine** to
reproduce the exact `dist/SoundSetter-v1.0.apk` produced from this repository,
without Gradle, Android Studio, or any pre-installed Android tooling beyond a
POSIX shell.

---

## 0. What gets built

| Property | Value |
|---|---|
| Artifact | `dist/SoundSetter-v1.0.apk` (≈ 57 KB, 7 entries) |
| Package | `com.tools.soundsetter` |
| App label | Sound Setter |
| versionCode / versionName | 1 / "1.0" |
| minSdk / targetSdk | 24 (Android 7.0) / 34 (Android 14) |
| Language / UI | Pure Java 8-compatible source, framework `android.view` widgets — **no AndroidX, no Gradle, no external runtime deps** |
| Signing | Self-signed RSA-2048 keystore **auto-generated by `build.sh`** (alias/password `soundsetter`), APK Signature Scheme v2 + v3 |
| Included libraries (dexed in) | Shizuku client API 13.1.5 (`dev.rikka.shizuku:{api,aidl,shared,provider}`) + `androidx.annotation` 1.3.0 (compile/dex only) |

> **Bit-exactness note:** each fresh machine generates a new keystore, and dex
> timestamps differ, so a rebuild is **functionally identical but not
> byte-identical** unless you supply the *same* keystore file (see §5). The
> `keystore/` directory and `dist/`, `build/` outputs are git-ignored build
> environment on purpose.

## 1. Requirements

- Linux or macOS shell with `bash`, `curl`, `unzip`, `tar` (Windows: WSL/Git-Bash).
- ≈ 600 MB disk, network access to these hosts (all links verified working):
  - `api.adoptium.net` — Temurin JDK 17 (originally **17.0.21+9**, x64 Linux)
  - `dl.google.com` — Android command-line tools, SDK platform 34, build-tools 34.0.0, `androidx.annotation`
  - `repo1.maven.org` — Shizuku 13.1.5 AARs
- **No** Gradle, Maven, Android Studio, AndroidX, root, emulator, or device are
  required to *build*. A device/emulator is only needed to smoke-test the APK.

## 2. One-shot toolchain setup

The build expects this exact layout (`build.sh` globs it):

```
$HOME/toolchain/jdk-*/                     # JDK 17 (any dir matching jdk-*)
$HOME/toolchain/shizuku-libs/api/classes.jar
$HOME/toolchain/shizuku-libs/aidl/classes.jar
$HOME/toolchain/shizuku-libs/shared/classes.jar
$HOME/toolchain/shizuku-libs/provider/classes.jar
$HOME/toolchain/shizuku-libs/annotation-1.3.0.jar
$HOME/android-sdk/platforms/android-34/android.jar
$HOME/android-sdk/build-tools/34.0.0/{aapt2,d8,javac-support?,zipalign,apksigner,...}
```

```bash
# --- 2.1 JDK 17 (Temurin) ---
mkdir -p "$HOME/toolchain" && cd "$HOME/toolchain"
curl -fL -o jdk17.tar.gz \
  "https://api.adoptium.net/v3/binary/latest/17/ga/linux/x64/jdk/hotspot/normal/eclipse"
tar -xzf jdk17.tar.gz                      # extracts to e.g. jdk-17.0.21+9/
rm jdk17.tar.gz

# --- 2.2 Android SDK (cmdline-tools + platform 34 + build-tools 34.0.0) ---
mkdir -p "$HOME/android-sdk/cmdline-tools"
cd "$HOME/android-sdk/cmdline-tools"
curl -fL -o cmdtools.zip \
  "https://dl.google.com/android/repository/commandlinetools-linux-11076708_latest.zip"
unzip -q cmdtools.zip
mv cmdline-tools latest                    # -> $HOME/android-sdk/cmdline-tools/latest
yes | latest/bin/sdkmanager --licenses > /dev/null
latest/bin/sdkmanager "platforms;android-34" "build-tools;34.0.0"

# --- 2.3 Shizuku client 13.1.5 + androidx.annotation ---
mkdir -p "$HOME/toolchain/shizuku-libs" && cd "$HOME/toolchain/shizuku-libs"
for a in api aidl shared provider; do
  curl -fL -o "$a-13.1.5.aar" \
    "https://repo1.maven.org/maven2/dev/rikka/shizuku/$a/13.1.5/$a-13.1.5.aar"
  mkdir -p "$a" && (cd "$a" && unzip -qo "../$a-13.1.5.aar" classes.jar)
done
curl -fL -o annotation-1.3.0.jar \
  "https://dl.google.com/dl/android/maven2/androidx/annotation/annotation/1.3.0/annotation-1.3.0.jar"
```

**Integrity check** (sizes of the files you just downloaded — must match
exactly; if a size looks like an HTML error page, `zip END header not found`
will follow — re-download):

| File | Bytes |
|---|---|

| `shared-13.1.5.aar` | 2614 |

## 3. Build

```bash
cd <repo-root>
chmod +x build.sh
./build.sh
```

`build.sh` (76 lines, readable top-to-bottom) runs:

1. **aapt2 compile** — compiles `app/src/main/res` (only a vector launcher icon) to `res.zip`.
2. **aapt2 link** — links `AndroidManifest.xml` against `android.jar`, stamps minSdk 24 / targetSdk 34 / versionCode 1 / versionName 1.0.
3. **javac** — `-source 8 -target 8 -bootclasspath android.jar`, classpath = the four Shizuku `classes.jar` + `annotation-1.3.0.jar`; compiles the 4 sources of `app/src/main/java`.
4. **d8** — dexes our classes **plus the Shizuku jars** (so Shizuku is bundled); `android.jar` and the annotation jar are `--lib` (compile-time only).
5. **pack + zipalign** — injects `classes.dex` into the APK (`zip`, falling back to `jar`), then `zipalign -p 4`.
6. **apksigner** — auto-generates `keystore/soundsetter.keystore` if absent (keytool, RSA-2048, validity 11000 days, CN=Sound Setter), signs v2+v3, then **verifies the signature** and prints `aapt2 dump badging`.

Success line: `OK -> .../dist/SoundSetter-v1.0.apk`.

## 4. Verification (what "good" looks like)

```bash
BT="$HOME/android-sdk/build-tools/34.0.0"
"$BT/apksigner" verify --verbose dist/SoundSetter-v1.0.apk
#  -> "Verifies"; v2 scheme: true; v3 scheme: true  (v1 false is EXPECTED: v2 exists from API 24)
"$BT/zipalign" -c -p 4 dist/SoundSetter-v1.0.apk && echo OK
"$BT/aapt2" dump badging dist/SoundSetter-v1.0.apk
```

Expected badging: `package name='com.tools.soundsetter'`, `sdkVersion:'24'`,
`targetSdkVersion:'34'`, permissions `WRITE_SETTINGS`, `READ_MEDIA_AUDIO`,
`READ_EXTERNAL_STORAGE (maxSdk 32)`, `WRITE_EXTERNAL_STORAGE (maxSdk 28)`,
`moe.shizuku.manager.permission.API_V23`, launchable-activity
`com.tools.soundsetter.MainActivity`.

Optional deeper check:

```bash
"$BT/dexdump" dist/SoundSetter-v1.0.apk | grep "Class descriptor"
# expect: Lcom/tools/soundsetter/MainActivity; Lcom/tools/soundsetter/SoundApplier;
#         Lcom/tools/soundsetter/ShizukuBridge; Lcom/tools/soundsetter/SoundEvent;
#         Lrikka/shizuku/Shizuku; Lrikka/shizuku/ShizukuProvider;
```

## 5. Reproducing the *same signature* (optional)

`keystore/` is intentionally git-ignored. If you need an APK signed with the
identical key across machines, place your `soundsetter.keystore` at
`keystore/soundsetter.keystore` **before** running `build.sh` (it only
auto-generates when the file is missing); alternatively export it from the
original build machine. Keep it out of version control if the repo is public.

| `app/src/main/res/drawable/ic_launcher.xml` | Vector launcher icon (no PNGs needed). |

| `app/src/main/java/com/tools/soundsetter/SoundApplier.java` | **The pipeline** (1005 lines): format detection → MediaStore publish → permission gate → write → read-back verify → MIUI slot fix-up → readability check; plus `ApplyResult` step log, error hints, Shizuku force-tier, current-setting reader. |
| `app/src/main/java/com/tools/soundsetter/MainActivity.java` | UI: event rows with current value + preview, file picker flow, permission state machine (WRITE_SETTINGS screen, runtime perms), progress/result/details dialogs with clipboard copy, system-ringtone-picker fallback, Shizuku status panel, troubleshooting dialog. |

| `build.sh` | The standalone pipeline (see §3). |
| `README.md` | User-facing docs + sources/credits. |
| `REBUILD.md` | This file. |
| `.gitignore` | Excludes `build/`, `dist/`, `keystore/`, `*.keystore` (build environment). |

## 7. How the app works (behavioral spec)

**Rows shown:** Call ringtone (`Settings.System.ringtone`), Notification sound
(`notification_sound` — used for received SMS/texts by apps on the default
sound), Alarm sound (`alarm_alert`), and — on Xiaomi/Poco/Redmi devices or when
the keys exist — SIM 1 / SIM 2 ringtone (`ringtone_sound_slot_1/2`).

**Per row:** current value is *read from the device* (Settings/System + the
MIUI slot keys), a ▶ Preview button plays it (media volume, restore after),
"Choose file" opens `ACTION_OPEN_DOCUMENT` with `*/*` (every format Android
recognizes).

**Apply pipeline (background thread, each step logged into the result report):**

1. **Format detection** — provider MIME (3 tries) → extension table
   (mp3/wav/ogg/oga/flac/m4a/aac/amr/3gp/mid/rmf/aiff…) → byte-sniffing
   (ID3/0xFF sync, RIFF/WAVE, OggS, fLaC, ftyp, `#!AMR`, `MThd`). Unknown →
   failure with re-encode hint. *Why:* `RingtoneManager` **silently no-ops**
   when MIME resolution fails (documented AOSP behavior).
2. **Publish to MediaStore** — Android 10+: insert into
   `VOLUME_EXTERNAL_PRIMARY` with `RELATIVE_PATH=Ringtones|Notifications|Alarms`,
   `IS_PENDING 1→0`, `IS_RINGTONE/IS_NOTIFICATION/IS_ALARM` flags, stream-copy,
   `MediaStore.createPending` fallback on retry; Android 7–9: public-dir write +
   `MediaScannerConnection` scan with `DATA`-insert fallback. Then
   `ContentResolver.getType()` must succeed (3×300 ms) or fail with the
   "MediaProvider hasn't indexed" error.
3. **Permission gate** — `Settings.System.canWrite()`; if false the UI had
   already routed through `ACTION_MANAGE_WRITE_SETTINGS`; failure includes the
   exact error text.
4. **Write** — `RingtoneManager.setActualDefaultRingtoneUri()` for standard
   events, **plus** MIUI per-SIM slot keys when present (they override the
   global key — the classic Xiaomi "set it, nothing changes" trap), **plus**
   `Settings.System.putString` for SIM rows.
5. **Verify by read-back** (this is what guarantees Settings reflects the new
   sound) — normalized comparison ignoring `content://0@` user prefixes and
   `external_primary` vs `external`. On mismatch: sleep+retry direct
   `Settings.System.putString`, sleep+re-run `RingtoneManager`, re-read.
6. **Elevated retry** — if still unverified and the user enabled Shizuku:
   `settings put system <key> <uri>` executed as shell uid 2000 via
   `IShizukuService.newProcess()`, then re-verify.
7. **MIUI slot verify/fix** (`verifyAndFixSlots`) — rewrites slot keys that
   still disagree, non-fatal warnings when OEM keeps its own value.
8. **Readability check** — `openAssetFileDescriptor` + one-shot decoder probe;
   playability problems become warnings, not failures.
9. **Cleanup** — the *previous* app-owned copy in the sound folder is deleted
   after success (order matters: read old → set new → remember new).

**Error handling:** every failure carries `stepId`, headline, human message,
"what to do" hint (incl. MIUI-specific steps), the underlying exception and the
full step log — shown in a Details dialog with clipboard copy. If the file made
it into MediaStore but the write was refused, a one-tap **system ringtone
picker** fallback (`ACTION_RINGTONE_PICKER` with your URI pre-loaded as
existing/default) hands the final privileged step to Android's own UI — all
still launched in-app, no other app or workflow required of the user.

**Supported versions:** Android 7.0–15 (minSdk 24, targetSdk 34, scoped
storage correct for 10+/13+, `READ_MEDIA_AUDIO` for 13+).
